# Техническое задание на учебное приложение

Версия 1.0 от 3 октября 2026 года. Репозиторий: https://github.com/imnotplastina/mini-app. Размещение: существующий проект mini-app на Vercel.

## Назначение и границы

Создать Telegram Mini App с библиотекой учебных разделов. В каждом разделе находятся статьи с изображениями и видеоуроки. Читатель открывает каталог, выбирает раздел, изучает урок и переходит к следующему. Контент доступен также в обычном браузере.

Рабочие допущения до получения уточнений: материалы открыты всем, язык русский, редактор управляет контентом через админку. Рабочее название «Практика» можно заменить без изменения архитектуры. Демонстрационные материалы посвящены организации обучения и должны быть заменены материалами заказчика перед запуском.

Оплата, подписки, домашние задания, тестирование знаний, рассылки, сертификаты и синхронизация прогресса не входят в первую версию.

## Пользовательские экраны

1. Каталог: приветствие, вводный блок, карточки разделов, список уроков, поиск по названию и описанию, фильтр по формату.
2. Раздел: название, описание, обложка и упорядоченный список опубликованных уроков.
3. Урок: название, тип, время изучения, статья или видео, предыдущий и следующий урок в том же разделе.
4. Профиль: имя и подтверждённый Telegram ID, состояние доступа к админке. При открытии вне Telegram — объяснение способа входа.
5. Админка: список разделов и уроков, редакторы, предварительный просмотр, публикация и снятие с публикации.

На пустые результаты поиска, пустой раздел, отсутствующий урок, ошибку загрузки и недоступное видео предусмотреть отдельные понятные состояния. Навигация должна работать по прямым ссылкам и после обновления страницы.

## Модель контента

Раздел: id, название, описание, обложка, цвет оформления, позиция, статус публикации, даты создания и изменения.

Урок: id, sectionId, название, описание, тип article/video, длительность в минутах, обложка, позиция, статус публикации, даты создания и изменения. Статья хранится как Markdown без исполнения HTML или JavaScript. Поддержать заголовки, абзацы, жирное и курсивное выделение, списки, цитаты, безопасные ссылки, изображения и подписи через соседние абзацы. Видео хранится как HTTPS URL на MP4; под плеером разрешён сопроводительный Markdown.

Все пользовательские строки ограничены по длине и проверяются на сервере. Статусы: draft/published. Неопубликованные уроки и уроки неопубликованных разделов исключаются из публичного каталога и недоступны по URL.

## Медиа

Изображения загружаются редактором в публичное Vercel Blob либо задаются HTTPS-ссылкой. Допустимые загрузки: JPEG, PNG, WebP, GIF до 4 МБ; SVG-загрузки не поддерживаются. Вставка в текст выполняется кнопкой редактора. Для иллюстраций нужен альтернативный текст.

Видео воспроизводится стандартным HTML5-плеером с controls и playsInline, без autoplay, с preload metadata. Предусмотреть обработку ошибки и повторный запуск. Полноэкранный режим предоставляется плеером в поддерживающих его клиентах. Видео размещается отдельно и поступает в приложение по прямому HTTPS URL; загрузка больших видео через серверные функции и интеграция сторонних iframe-плееров вне объёма первой версии.

## Администрирование

Вход через Telegram. Список Telegram ID администраторов задаётся серверной переменной ADMIN_TELEGRAM_IDS. Пользователь может увидеть свой ID на странице профиля после успешной проверки Telegram.

Редактор создаёт и изменяет разделы и уроки, задаёт числовой порядок, переносит урок в другой раздел, проверяет предварительный просмотр и переключает публикацию. Необратимое удаление не требуется: материалы снимаются с публикации. Изменения сохраняются в SQLite и переживают новые развёртывания. Для предотвращения незаметной потери параллельных правок использовать проверку версии документа.

## Архитектура

Next.js App Router, React, TypeScript. Серверные обработчики и интерфейс на Vercel, SQLite для данных, Vercel Blob для загружаемых изображений. Секреты находятся только в переменных окружения. Подключение к базе задаётся DATABASE_URL; для удалённой libSQL также DATABASE_AUTH_TOKEN.

Локально используется файл SQLite (DATABASE_URL=file:local.db). На Vercel требуется удалённая libSQL/SQLite, например Turso: постоянного локального диска у функций Vercel нет. Файловое подключение на Vercel запрещается приложением.

Без подключения базы доступен демонстрационный каталог из репозитория. Он явно обозначен как пример. Запись в этом режиме запрещена; приложение не имитирует успешное сохранение. При ошибке настроенной базы приложение показывает ошибку, а не подменяет реальные данные демонстрационными.

Проверять HMAC Telegram initData, уникальность полей, auth_date и идентификатор пользователя. Срок приёма initData — один час, допустимое отклонение часов — 30 секунд. После проверки выдавать серверную подписанную сессию на 8 часов в HttpOnly cookie. Cookie Secure в production и SameSite=Lax. Любая запись требует действующей сессии, проверки ADMIN_TELEGRAM_IDS и same-origin запроса. Не доверять initDataUnsafe. Секрет сессий SESSION_SECRET не короче 32 символов.

## Оформление и доступность

Приоритет — мобильный экран от 360 px, также поддержать планшет и desktop. Спокойный интерфейс с тёплым фоном, зелёными акцентами и выразительной типографикой. Светлая и тёмная темы, уважение системной темы и Telegram colorScheme. Кнопка «Назад» Telegram повторяет навигацию приложения. Учитывать безопасные области экрана. Все формы имеют подписи, интерактивные элементы — видимый focus, анимации отключаются при prefers-reduced-motion.

## Vercel и Telegram

Production-ветка main. Для Next.js используется автоматическое определение фреймворка. Основные команды: npm ci, npm run build, npm start. Инициализация таблиц — отдельная идемпотентная команда npm run db:init, заполнение демонстрационными материалами — отдельная команда npm run db:seed. Автоматически добавлять демо в production нельзя.

Переменные: TELEGRAM_BOT_TOKEN, SESSION_SECRET, ADMIN_TELEGRAM_IDS, DATABASE_URL, DATABASE_AUTH_TOKEN, BLOB_READ_WRITE_TOKEN. Окружения Preview и Production должны использовать разные данные и секреты. Нужен публичный production HTTPS URL без авторизации Vercel. Токен, опубликованный в переписке, перед запуском перевыпустить через BotFather.

Пользователь уже настроил ссылку бота. Проверить Main Mini App и Menu Button на окончательный production URL. Webhook не требуется для меню приложения; автоматический ответ бота на /start в текущую версию не входит.

## Приёмка

- Каталог, поиск, фильтры, разделы и уроки работают в браузере и Telegram.
- Статья с несколькими изображениями читается без горизонтальной прокрутки на 360 px.
- Видео запускается вручную, поддерживает перемотку и понятное состояние ошибки.
- Предыдущий и следующий урок учитывают порядок и публикацию в одном разделе.
- Администратор создаёт, редактирует, просматривает и публикует материалы без изменения кода.
- Пользователь без прав не читает черновики и не изменяет данные, в том числе прямыми API-запросами.
- Поддельная или устаревшая Telegram-подпись отклоняется.
- Сохранённые материалы доступны после нового развёртывания; конфликт правок не перезаписывает документ молча.
- Проверки типов, production-сборка и автоматические тесты безопасности/видимости проходят.
- На реальных Telegram iOS и Android отдельно проверить запуск, безопасные отступы, изображения, видео и вход администратора. Эти проверки требуют настроенного бота и инфраструктуры.

## Внешние зависимости запуска

Заказчик предоставляет окончательные тексты, картинки, видео, название и Telegram ID администратора. Владелец проекта подключает SQLite и Blob, сохраняет перевыпущенный токен и остальные секреты в Vercel. До этого можно проверить демонстрационный каталог и код, но нельзя подтвердить production-запись и реальный вход через Telegram.
